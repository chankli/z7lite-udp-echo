# Z7-LITE UDP Echo / Streaming Example

A self-contained MicroPhase Z7-LITE example for the
[`udp_axis_complete`](rtl/udp_axis_complete.v) UDP/AXIS wrapper.

* FPGA: Xilinx Zynq-7000 **XC7Z020-1CLG400C**
* PHY: Realtek **RTL8201F**, 10/100 Mbps MII
* Board: MicroPhase Z7-LITE R11
* Logic clock: 50 MHz PL clock
* UDP echo: `192.168.10.128:1234` -> fixed `ECHO_DEST_IP`
  (`192.168.10.100` by default)
* ARP and ICMP echo are handled by the UDP stack
* Per-packet AXIS `TDEST` carries `{source_port, destination_port}`
* 4096-byte TX FIFO, payloads up to 1472 bytes
* Optional 4096-sample ILA and an MDIO master

This repository vendors the upstream `verilog-ethernet` RTL it needs under
`vendor/verilog-ethernet`, so it builds without the original repository or
a `lib/eth` symlink.

## Quick start

### Requirements

* Xilinx Vivado 2024.2 (the design also uses the `ila` IP)
* Python 3 (host test scripts)
* Optional: ModelSim/Questa for the self-checking testbench
* PC Ethernet adapter: `192.168.10.100/24`
* Board: `192.168.10.128/24`

### Build

From the repository root:

```bash
make
```

The Vivado project is generated by the Makefile flow (there is no committed
`.xpr`).  The output is:

```text
fpga/fpga/fpga.bit
fpga/fpga/fpga.ltx
```

The `fpga/fpga/Makefile` builds with `FPGA_PART = xc7z020clg400-1` and
`FPGA_TOP = fpga`.  The project is re-created from
`fpga/common/vivado.mk` and the source/XDC lists, so a clean checkout can
rebuild it with one `make`.

### Program

```bash
make program
```

The generated `program.tcl` selects the PL device (`xc7z020_1`) and loads
the matching `.ltx` probes file if present.

### Test

From the repository root:

```bash
ping 192.168.10.128
python tools/udp_echo_test.py
python tools/udp_stress_test.py --count 2000
python tools/udp_stress_test.py --sizes 1472 --count 10000 --pps 8000
```

The PC Ethernet adapter must be `192.168.10.100/24` because the echo reply
goes to the fixed `ECHO_DEST_IP`.

## Verified results

Self-checking testbench (`tb/udp_axis_complete`, ModelSim/Questa):

```text
TX_BASIC PASS
TX_PORTS PASS
TX_BACKTOBACK PASS
RX_BASIC PASS
RX_FILTER PASS
ICMP_PING PASS
ICMP_REJECT PASS
ICMP_BACKPRESSURE PASS
TX_OVERFLOW PASS
ARP_FAIL PASS
TESTS: 0 errors
```

Hardware on the Z7-LITE (100M MII, 50 MHz logic clock):

| Test | Result |
|------|--------|
| 1472 B, 10000 packets, `--pps 8000` | 0% loss, 94.1 Mbps payload, 98.35 Mbps wire, ~1 ms latency |
| 64 B, maximum rate | 0% loss, 46.3 Mbps payload, 94.0 Mbps wire |
| 128 B / 256 B, maximum rate | 0.2% / 0.8% loss, ~99 Mbps wire |
| 512 B+ without pacing | link saturated at ~99.7 Mbps wire; drops because the PC offers more than 100M |

The 100M MII link is the throughput limit.  Small-packet rates are also
limited by the Python sender/receiver, not by the FPGA.

## Important board note: RTL8201F RMII strap

The RTL8201F latches its MII/RMII mode at power-on from the **RXDV pin
(pin 26)**.  On this board the mode strap is exposed through **JP1 pin 37**
(net `GPIO1_16P`, FPGA pin V13 = **PUDC_B**) and is **floating by default**.
A floating PUDC_B can enable the FPGA configuration-time user-I/O pull-ups;
FPGA K18 then pulls `ETH_RXDV` high, and the PHY latches **RMII**.  In RMII
mode TXC is an input, so both MII clocks are dead and the MAC sees no data.

Hardware fix:

```text
JP1 pin 37 (PUDC_B) -- 4.7K -- JP1 pin 29 (VCC_3V3)
```

Power-cycle after fitting the strap.

Software fallback (already included): `rtl/mdio_master.v` reads the
RTL8201F Page 7 Register 16 (RMSR), sees bit 3 = 1 (RMII), clears it to
force MII, and then reads BMSR.  With the hardware strap fitted, RMSR
bit 3 is already 0 and the MDIO master simply leaves it alone.  See the
design notes in [fpga/README.md](fpga/README.md) and the MDIO/RMII
investigation comments in `fpga/rtl/fpga_core.v`.

## Future: 1G RGMII

The current build is 100M MII.  For a future 1G RGMII PHY, see
[docs/rgmii-migration.md](docs/rgmii-migration.md).  The RGMII RTL and
timing Tcl are already vendored, and `docs/reference/` contains the
NexysVideo 1G RGMII top/core/XDC reference, which uses the same
`udp_axis_complete`.

The short version:

* replace `eth_mac_mii_fifo` with `eth_mac_1g_rgmii_fifo`
* generate 125 MHz and 125 MHz 90-degree clocks
* keep `udp_axis_complete` at 8-bit / 125 MHz
* replace the MII pins/timing with RGMII pins/timing
* update MDIO and remove the RTL8201F-specific RMII workaround

## Notes

* `make` generates the Vivado project; do not commit `fpga/fpga/*.xpr`,
  runs, caches, bitstreams, or logs.  The provided `.gitignore` covers
  these.
* On Windows, use Git Bash/MSYS for `make`, and make sure the Xilinx
  `vivado`/`vivado.bat` wrapper is in `PATH`.
* To build without the debug ILA, set `.DEBUG_ILA(0)` in
  `fpga/rtl/fpga.v` and rebuild.  The production bitstream then has no ILA
  or `.ltx`.
